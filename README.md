# CSV Merge & FTP Uploader

Асинхронная утилита на Python для автоматического поиска, валидации и объединения CSV-файлов по заданным шаблонам с последующей выгрузкой результата на FTP-сервер и отправкой уведомлений в Telegram.

Проект поддерживает систему **Overlay-конфигураций**, позволяющую использовать один базовый `.env` файл и переопределять параметры для разных магазинов, складов или окружений (например, `.env.shop1`, `.env.allshops`).

---

## Основные возможности

* **Гибкая система конфигураций (Overlay):** загрузка базовых настроек из `.env` и наложение поверх них специфичных параметров из директории `env/` (файлы формата `.env.<имя>`).
* **Поиск и слияние CSV:** рекурсивный поиск файлов по регулярному выражению, объединение данных, точное суммирование остатков (через `Decimal` с настраиваемым округлением) и приведение колонок к эталонному шаблону.
* **Контроль качества данных:**
  * Проверка актуальности файлов (контроль времени последней модификации по `INACTIVITY_LIMIT_HOURS`).
  * Валидация значений ширины (от 0 до `DATAS_MAX_WIDTH`) и извлечение состава товара.
  * Автоматическая проверка разделителей в шаблоне заголовков.
* **Асинхронная выгрузка на FTP:** загрузка итогового файла на сервер через `aioftp` с обработкой ошибок авторизации и сети.
* **Уведомления в Telegram:** отправка статусов выполнения, алертов о выходе ширины за пределы и предупреждений об устаревших файлах (поддержка `Markdown`, `MarkdownV2`, веток супергрупп `chat_id/thread_id` и прокси-серверов).
* **Автоматизация окружения:** встроенный менеджер (`venv_manager.py`) для создания виртуального окружения, установки зависимостей и запуска основного скрипта.

## Структура проекта

```text
├── config.py             # Синглтон Config и класс OverlayConfig для работы с .env
├── merge_csv.py          # Основной модуль: поиск, валидация, слияние CSV и запуск пайплайна
├── load_to_ftp.py        # Асинхронная работа с FTP (загрузка, листинг файлов)
├── send_message.py       # Отправка уведомлений в Telegram через aiohttp (с поддержкой SOCKS/HTTP proxy)
├── logger.py             # Настройка ротируемого файлового и цветного консольного логирования
├── execution_time.py     # Декоратор для замера времени выполнения синхронных и асинхронных функций
├── run.py                # Точка входа: развертывание .venv, установка зависимостей и запуск проекта
├── requirements.txt      # Зависимости проекта
├── .env                  # Базовый файл конфигурации
└── env/                  # Директория с overlay-конфигурациями (например, .env.ALLSHOPS)
```

## Установка и запуск

### 1. Автоматический запуск (рекомендуется)
Скрипт `venv_manager.py` самостоятельно создаст виртуальное окружение (с привязкой к имени пользователя ОС или общее), обновит `pip`, установит зависимости из `requirements.txt` и запустит `merge_csv.py`:

```bash
# Запуск для всех конфигураций из папки env/
python run.py

# Запуск для конкретных конфигураций (например, .env.shop1 и .env.shop2)
python run.py --config shop1 shop2

# Запуск без добавления имени пользователя к папке .venv
python run.py --no-individual
```

### 2. Ручной запуск
```bash
python -m venv .venv
# Активация для Windows:
.venv\Scripts\activate
# Активация для Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
python merge_csv.py --config ALLSHOPS
```
*(Если запустить `python merge_csv.py` без флага `--config`, скрипт последовательно обработает все файлы `.env.*`, найденные в каталоге `ENV_DIR`).*

## Настройка конфигурации (`.env`)

Создайте базовый файл `.env` в корне проекта. Для каждого отдельного магазина или задачи создайте файл `.env.<NAME>` в папке `env/` (указывается только изменяемая часть параметров).

### Параметры CSV и данных

| Переменная | Описание | Пример / По умолчанию |
| :--- | :--- | :--- |
| `ENV_DIR` | Папка с overlay-конфигами | `env` |
| `CSV_PATH_TEMPLATE_DIRECTORY` | Путь к директории с эталонным шаблоном заголовков | `c:\ProgramData\...\Upload\` |
| `CSV_PATH_TEMPLATE_FILE` | Имя файла шаблона заголовков | `import_data.csv` |
| `CSV_PATH_DIRECTORY` | Директория для поиска исходных CSV-файлов | `C:\SoftLand Systems\...\Upload\` |
| `CSV_FILE_PATTERN` | Регулярное выражение для отбора исходных файлов | `^(MSK-TL-.*)\.csv$` |
| `CSV_FILE_NAME_FOR_FTP` | Имя итогового файла (поддерживает формат даты `strftime`) | `import_data.csv` |
| `CSV_FILE_ENCODING` | Кодировка CSV-файлов | `windows-1251` (дефолт `utf-8`) |
| `CSV_FILES_MIN_NUMBER` | Минимальное ожидаемое число файлов (влияет на статус в TG) | `2` |
| `CSV_SEPARATOR` | Общий разделитель колонок (можно задать раздельно `CSV_SEPARATOR_IN` и `CSV_SEPARATOR_OUT`) | `;` |
| `DATAS_COL_SKU` | Имя колонки с артикулом / ключом группировки | `Номенклатурный номер` |
| `DATAS_COL_QUANTITY` | Имя колонки с количеством для суммирования | `Количество` |
| `DATAS_COL_WIDTH` | Имя колонки с шириной | `Ширина` |
| `DATAS_COL_COMPOUND` | Имя колонки с составом (опционально) | `Состав` |
| `DATAS_MAX_WIDTH` | Максимально допустимая ширина товара | `220` |
| `DATAS_DECIMAL_PLACES` | Количество знаков после запятой при суммировании | `2` |
| `INACTIVITY_LIMIT_HOURS` | Порог неактивности файла в часах до отправки предупреждения | `24` |

### Параметры FTP

| Переменная | Описание | Пример / По умолчанию |
| :--- | :--- | :--- |
| `FTP_ENABLED` | Включение/отключение выгрузки (`1`, `true`, `yes`, `on`) | `True` |
| `FTP_HOST` | Адрес FTP-сервера | `ftp.example.com` |
| `FTP_PORT` | Порт FTP-сервера | `21` |
| `FTP_USER` | Имя пользователя FTP | `ftp_user` |
| `FTP_PASS` | Пароль FTP | `ftp_password` |
| `FTP_PATH` | Целевая директория на сервере | `/` |

### Параметры Telegram

| Переменная | Описание | Пример / По умолчанию |
| :--- | :--- | :--- |
| `TELEGRAM_TOKEN` | Токен бота от @BotFather | `123456:ABC-DEF...` |
| `TELEGRAM_CHAT_ID` | ID чата (для топиков используйте формат `chat_id/thread_id`) | `-100123456789/42` |
| `TELEGRAM_PARSE_MODE` | Режим разметки сообщений (`Markdown`, `MarkdownV2`, `HTML`) | `Markdown` |
| `PROXY` | Прокси для подключения к API Telegram (опционально) | `http://user:pass@ip:port` |

### Параметры логирования

| Переменная | Описание | Пример / По умолчанию |
| :--- | :--- | :--- |
| `LOG_DIR` | Директория сохранения логов (поддерживает `strftime`) | `logs\%Y\%Y.%m` |
| `LOG_FILE` | Шаблон имени лог-файла (автоматически добавляется имя пользователя ОС) | `merge_log_%Y.%m.%d.log` |
| `LOG_LEVEL_ROOT` | Корневой уровень логирования | `DEBUG` |
| `LOG_LEVEL_CONSOLE` | Уровень вывода в консоль | `DEBUG` |
| `LOG_LEVEL_FILE` | Уровень записи в файл (ротация по 10 МБ, до 5 бэкапов) | `WARNING` |
| `LOG_DATE_FORMAT` | Формат даты и времени в логах и уведомлениях | `%Y.%m.%d %H:%M:%S` |

## Требования и зависимости

* **Python:** 3.11 или выше
* **Основные библиотеки** (фиксируются в `requirements.txt`):
  * `pandas~=2.3.3`, `numpy~=2.3.5` - обработка и агрегация табличных данных
  * `aioftp~=0.26.3` - асинхронная работа с FTP
  * `aiohttp~=3.13.3`, `aiohttp_socks~=0.11.0` - отправка уведомлений в Telegram (включая работу через прокси)
  * `aiofiles~=24.1.0` - асинхронное чтение файлов
  * `python-dotenv~=1.1.1` - загрузка и наложение `.env` конфигураций
  * `colorlog~=6.9.0`, `colorama~=0.4.6` - цветное форматирование логов в консоли
